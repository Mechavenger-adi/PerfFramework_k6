# CLI Command Surface (Mini-EDD)

**Purpose.** Single Commander program registering every user-facing command; a bare invocation on a
TTY launches the interactive panel, non-TTY falls through to help (CI-safe).

**Owning files.** `cli/run.ts` (registry), + per-command handlers: `init.ts`, `new.ts`, `generate.ts`,
`generate-byos.ts`, `convert.ts`, `correlate.ts`, `import.ts`, `interactive.ts`, `validate.ts`,
`templates.ts`, `features.ts`, `config-inspect.ts`, `docs.ts`, `LifecyclePrompt.ts`.

**Entry point + condensed runtime flow (§4A).**
1. `program` built in [run.ts](../../core_engine/src/cli/run.ts); bare action → interactive panel on TTY, else `outputHelp()` ([run.ts:68-78](../../core_engine/src/cli/run.ts#L68)).
2. Commands registered via `.command().description().option().action()` — `init` [:97], `generate <team> <script>` [:154], `correlate` (`--list`/`--apply <level>`/`--script`/`--har`/`--log`) [:166-176], `convert` [:142], `import curl|postman` [:196-218], `run` (load execution).
3. Each `.action()` is a thin orchestrator that delegates to the engine/handler — no business logic in `run.ts`.

**Key types.** Commander `Command`; per-handler option objects.

**Configuration + env influence.** `--dir`, `--in-place`, `--apply`, `--curl/--file/--stdin/--clipboard`
per command; workspace detection (needs `config/` or `testSuites/`).

**Extension points.** Add a command = one `.command()` block + a handler module; register in `run.ts`.
See [extension-points.md](../../ai_context/extension-points.md).

**Known limitations.** No central command metadata table yet → L3 `cli-reference` must be generated by
parsing these registrations (Phase 3).

**Risks.** RZ2 (entry-script generation for `run` determines data-file path resolution).

**Tests to run.** Manual: `npm run cli -- --help`; each command smoke path.
